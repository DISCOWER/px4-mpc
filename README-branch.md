This package contains an MPC integrated with with [PX4 Autopilot](https://px4.io/) and [ROS 2](https://ros.org/).

The MPC uses the [acados framework](https://github.com/acados/acados)

# Specifics of branch
This branch contains the development and testing framework for Control Barrier Function (CBF) safety filters and a Model Predictive Control (MPC) implementation for fixed-wing UAV's.

The control architecture uses a reduced-order kinematic model of the fixed-wing for high-level path planning, which is cascaded with low-level incremental Nonlinear Dynamic Inversion (iNDI) controllers.

Two CBF's are implemented:
1. Higher-order CBF for stall protection with a minimum airspeed
2. Composite CBF for stall protection and minimum altitude (1st order)

and can be included in the MPC cost formulation and/or implemented as a shield layer to modify an input sequence that was generated by either the MPC rollout, or manual input held for the repair horizon to ensure forward invariance of safe sets.

## Setup (Build from source)
The environment setup and build is identical as [setup instructions in main branch](https://github.com/DISCOWER/px4-mpc/#setup) - follow their steps for configuring:
- ROS2 environment
- `git clone` relevant packages (`px4_msgs`, `px4-offboard`) and this branch in your ros2 workspace
- Install QGroundControl
- Set up Micro XRCE DDS agent ([documentation](https://docs.px4.io/main/en/ros2/user_guide#setup-middleware))
- Install `PX4Autopilot`: install prerequisites according to [main branch](https://github.com/px4/px4-autopilot). **This branch uses a detached branch for an Albatross UAV. Contact the [ARP Laboratory](https://github.com/arplaboratory) for more.**

NOTE: For custom/detached PX4Autopilot libraries, you may need to manually sync custom messages for ROS2 packages:
```
cd px4_msgs/
rm -f msg/*.msg srv/*.srv
cp ~/PX4-Autopilot/msg/*.msg msg/
cp ~/PX4-Autopilot/msg/versioned/*.msg msg/
cp ~/PX4-Autopilot/srv/*.srv srv/
```

## Running demonstrations

### Simulation test scripts
To visualize the CBF safety filter behavior and solver diagnostics outside of the full SITL environment, run the testing dashboards:

![fw-solver](https://github.com/user-attachments/assets/d6013b41-d92a-437f-ab85-7b6dbce2dfe7)
- `python3 test_fw_solver.py`: Path-following by a reduced-order kinematic model used by the MPC and safety filter (higher-order CBF for stall protection) is tested in a loop with an architecture inspired by [Shield-MPPI](https://arxiv.org/abs/2302.11719)

![filter-test](https://github.com/user-attachments/assets/2b3a4a8a-53ed-457e-b9a7-b28430c10a1b)
- `python3 test_filter.py`: evaluate CBF's in open-loop modifying a flat input for customizable range of test cases (orientation, control input, wind)

located in `px4_mpc/px4_mpc/test/`.

### SITL
Start the following in separate terminals:
1. DDS interface of PX4:
```bash
micro-xrce-dds-agent udp4 --port 8888
```
2. QGroundControl: methods vary by installation. for custom docker image, simply run:
```bash
qgroundcontrol
```
3. PX4 Simulation:
```bash
cd ~/PX4-Autopilot
make px4_sitl gz_advanced_plane
```
4. ROS2 Nodes (start the MPC implementation + rviz):
```bash
ros2 launch px4_mpc mpc_fixedwing_launch.py
```

Then, in the same terminal where you started the PX4 SITL, you can control the aircraft using the following commands:
- To arm the vehicle:
```bash
commander arm
```
- To follow the MPC setpoints:
```bash
commander mode offboard
```

## Docker and workflow
### Docker
The docker image is built from `nvidia/cuda:13.0.0-cudnn-devel-ubuntu22.04` with an Ubuntu 22.04 environment with cuda installed. 

Content size: 10.3 GB, Disk Usage: 33.3GB.

The `Dockerfile` and `docker-compose.yaml` is set up in a file directory like so:
```text
~/host_folder:
├── bags
├── build
├── docker-compose.yaml
├── Dockerfile
├── install
├── log
└── src
```
and additionally mounts the following volumes from host: `PX4Autopilot` and `.ssh`

It's highly recommended to use `ros2 plotjuggler` for analyzing current or recorded simulations.
(custom layout provided in `/config/debug-safety.xml`)

Additional workflow automation can be done using VS Code tasks and custom bash scripts.
